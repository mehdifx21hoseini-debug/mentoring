# MetaFactory 3.64.3 preview

Changes are limited to recovery and presentation of a fresh live feed whose full MT4 history is unconfirmed.

- MT4 live observer 1.06 no longer treats the first successful All History Windows command as a permanent history selection. If the current scan is incomplete, no All History request has succeeded, or the history sum no longer reconciles to balance, it can re-request All History. Requests are throttled to at most one per ten seconds, subject to the existing two/30-second history-poll backoff. Healthy scans do not repeatedly change the history filter.
- Recovery resets for a new observer session. DLL permissions are not changed. Existing full-history balance reconciliation, stable source signature, export revalidation and publication proof remain mandatory. An unverified history is never relabelled as verified.
- During fresh identity-matched history-pending reception, main-list Balance, current open-position count, floating P/L and current-stop warning can update from the current heartbeat without waiting for historical calculations. The footer has green Live, the explicit syncing state and the actual receipt age in seconds. Complete daily result and daily trade count stay unknown. Tooltips explicitly distinguish floating P/L and previous verified-history drawdown from a complete current daily report. Stale, future, disconnected or mismatched data cannot receive this override.
- A bounded history-status.txt in the active session directory records scan/request/DLL/reconciliation/publication state, sum, balance and difference. It is overwritten, never appended; unchanged reasons are written at most every30 seconds. System check reads only the active session's file, with a2048-byte read bound. No credentials are written.
- Native MT5 observer, MT4 full-history arithmetic/export, live frame reader/proof acceptance, normal report scripts, financial calculations, launch/close paths, bots, imports, Excel scope and storage policy remain unchanged. No faster polling, new per-row controls, timers, terminal restarts or process launches were added.

Activation: install the update. For an already-running MT4 observer, close and reopen only the affected reporting terminal through MetaFactory once, when convenient. The normal startup path compiles/deploys the new content-addressed MT4 observer using the installed MetaEditor. An app update alone does not hot-replace an EA already running inside MT4. Keep the normal history-completeness checks enabled; changing the displayed freshness label cannot repair broker-side missing history.

Validation: executable C++ mocks run the actual MQL recovery function bodies for filter truncation after successful startup, rate limiting, healthy scans, missing/restored DLL permission, failed requests, tick-counter wrap and persistent mismatch. Pending-feed model and actual MainForm tests cover MT4/MT5 cost handling, advancing values without baseline, unknown daily totals, real freshness, no-SL, identity/time/disconnection guards and bounded diagnostics. English/Persian at normal/125%. Main application tests, prior open-stop and report-status regressions pass; Framework4.5 build and installer payload/resource identity checked.

Limits: synthetic Mono/Linux GUI and mocked terminal API; MetaEditor compilation and this user's native Windows/broker recovery require validation on the affected computer. The supplied diagnostic proves fresh heartbeats with native history-unconfirmed, but does not contain the history sum or the native rejection branch. Lost/truncated history selection is a reproducible code recovery weakness, not a proven sole cause for those two accounts. Persistent mismatch remains explicitly unconfirmed with a precise recovery diagnostic. Zero network/broker/rendering latency is not guaranteed.
