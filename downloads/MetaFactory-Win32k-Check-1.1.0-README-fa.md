# بررسی رویداد Win32k — نسخه 1.1.0

این ابزار سوابق موجود و شمارندهٔ فعلی منابع نام‌گذاری پنجره‌ها در ویندوز را فقط می‌خواند. لازم نیست متاتریدرها را دوباره باز کنید یا مشکل را تکرار کنید. نسخهٔ MetaFactory همان3.69.10 باقی می‌ماند.

## روش استفاده

فایل `MetaFactory-Win32k-Check-1.1.0.exe` را یک بار اجرا کنید. پنجره‌ای باز نمی‌کند. پس از چند ثانیه باید فایل `MetaFactory-Win32k-Events.txt` روی Desktop ایجاد شود؛ همان فایل را برای بررسی ارسال کنید. این فایل با گزارش ابزار قبلی `MetaFactory-Window-Test.txt` فرق دارد.

اگر Desktop قابل نوشتن نباشد، خروجی در `%APPDATA%\MT Manager` با همان نام قرار می‌گیرد. اگر هیچ فایل جدیدی ایجاد نشد، ابزار موفق به ذخیره گزارش نشده است؛ موفقیت یا نبودن خطا فرض نشود.

## دلیل این بررسی

راهنمای رسمی مایکروسافت، رویداد243 در System log با منبعWin32k را نشانهٔ شکست تخصیص desktop heap معرفی می‌کند. این رویداد ممکن است فقط یک بار در نشست ثبت شود و ساعت‌ها پیش از علامت ظاهری باشد؛ به همین دلیل این ابزار سوابق نگه‌داری‌شده را بدون محدودکردن به زمان اجرای اخیر MetaFactory می‌خواند.

منبع: https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/desktop-heap-limitation-out-of-memory

نسخهٔ مستندات رسمی بررسی‌شده در این کار از مخزن MicrosoftDocs/SupportArticles-docs است. راهنما تأکید می‌کند مقدار دوم SharedSection بالاتر از20480KB تنظیم نشود. این ابزار هیچ مقدار رجیستری را تغییر نمی‌دهد.

## شمارندهٔ User Atom Table

طبق راهنمای رسمی Microsoft، جدول مشترک دیگری برای نام کلاس‌های پنجره، پیام‌ها و قالب‌های ثبت‌شده وجود دارد. پرشدن این جدول می‌تواند ایجاد پنجره و اجرای برنامه‌ها را مختل کند. تست قبلی با کلاس آمادهSTATIC، ثبت نام کلاس جدید را بررسی نمی‌کرد.

این ابزار شناسه‌های0xC000تا0xFFFF را باGetClipboardFormatNameW می‌خواند؛ این روش در مستنداتMicrosoft برای بررسی جدولUser Atom پیشنهاد شده است. فقط تعداد نام‌های قابل‌خواندن و گروه‌های از پیش تعیین‌شده ثبت می‌شود؛ نام‌ها بلافاصله کنار گذاشته می‌شوند. محتوای کلیپ‌بورد خوانده نمی‌شود و هیچ قالب، کلاس یاAtom ساخته یا حذف نمی‌شود. گروه‌بندی اسم‌ها نشان‌دهنده مالک یا مقصر قطعی نیست.

منبع: https://learn.microsoft.com/en-us/windows/win32/dataxchg/about-atom-tables

این شمارنده اندازه یا مقدار آزادdesktop heap نیست. خطای دسترسی یا ناتمام‌بودن اسکن جدا ثبت می‌شود. پر بودن جدول فعلاً یک فرضیه برای بررسی است، نه علت اثبات‌شده. بعضی نام‌های ثبت‌شده تا پایان نشست ویندوز باقی می‌مانند؛ قبل از ثبت نتیجه، نیازی به خروج از حساب یا ری‌استارت نیست.

## محدوده و محدودیت

- فقط رویداد243 از دو نام دقیق منبعWindows یعنیWin32k وMicrosoft-Windows-Win32k در کانالSystem جمع‌آوری می‌شود. کانالSecurity، اطلاعات حساب معاملاتی، رمز، خط فرمان و عنوان پنجره‌ها خوانده نمی‌شوند.
- متن خود رویدادWindows ممکن است نام فرایند و شناسه نشست را داشته باشد. این‌ها برای تطبیق علت و زمان لازم‌اند. شناسهProcessId سربرگ رویداد لزوماً شناسه متاتریدر مشکل‌دار نیست؛ متن رویداد باید بررسی شود.
- وجود رویداد باید با زمان و نشست آزمایش تطبیق داده شود. نبود رویداد، نبود مشکل منابع را اثبات نمی‌کند؛ نسخهٔ ویندوز، دسترسی و نگه‌داری لاگ نیز مؤثرند.
- خطای دسترسی یا خواندن جدا از نتیجهٔ «رویداد پیدا نشد» ثبت می‌شود. حداکثر256رویداد با این شماره،64رویدادWin32k و حدود10ثانیه برای رویدادها و5ثانیه برای شمارنده بررسی می‌شود؛ رسیدن به حد با علامت ناقص‌بودن ثبت می‌شود.
- نسخه‌های ویندوز ممکن است این رویداد را متفاوت ثبت کنند؛ مستندات مرجع برای Windows Server است و تشابه علائم به‌تنهایی برای نسبت‌دادن خطا به ویندوز10 کافی نیست.
- هیچ برنامه‌ای باز یا بسته نمی‌شود، پنجرهٔ آزمایشی ساخته نمی‌شود، رجیستری/مجوزها تغییر نمی‌کنند و درخواست شبکه وجود ندارد. Administrator به‌طور خودکار درخواست نمی‌شود.
- حداکثر256کیلوبایت برای فایل جاری و همین مقدار برای یک فایل قبلی؛ فایل ناشناخته موجود بازنویسی نمی‌شود.

ساخت علیه Reference assemblies دات‌نت4.5 و تست با خوانندهٔ ساختگی درMono/Linux انجام شده است؛ دسترسی واقعی به Event log ویندوز در این محیط آزمایش نشده است.

## سورس

`source/Win32kCheck.cs` ابزار و `source/Tests.cs` آزمون‌هاست. `source/build.sh` باMono ساخته می‌شود؛ `MF_REF45` مسیر اختیاری Microsoft .NET Framework4.5Reference Assemblies است. در ویندوز می‌توان باcsc و ارجاع بهSystem.Core.dll وSystem.Web.Extensions.dll ساخت.
