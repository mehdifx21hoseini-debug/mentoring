# MetaFactory 3.60.0 preview — ورود از متن و ثبت فقط پس از تأیید ورود

## استفاده

۱. فلش کنار «دانشجوی جدید» → «افزودن از متن…» را بزنید. در پنجرهٔ ورود اکسل هم دکمهٔ «چسباندن متن…» هست.
۲. پیام چند دانشجو را یک‌جا بچسبانید و «خواندن متن و پیش‌نمایش» را بزنید. برای این کار توکن هوش مصنوعی یا فایل اکسل لازم نیست.
۳. اطلاعات در جدول قابل‌ویرایش نمایش داده می‌شوند. نام، پلتفرم، شماره حساب و سرور را مستقیم اصلاح کنید؛ «ویرایش ردیف» رمزها، نوع ورود، نام اصلی و پوشه را هم در دسترس می‌گذارد.
۴. «بررسی و افزودن آماده‌ها» را بزنید. فقط حسابی که ورودش مستقیماً تأیید شود ثبت می‌شود. ردیف ناقص، ردشده، قطع یا تأییدنشده وارد فهرست اصلی نمی‌شود؛ مشکل یک نفر جلوی دیگران را نمی‌گیرد.
۵. با کلیک وضعیت ناموفق و آیکون کپی، اطلاعات و درخواست اصلاح همان نفر را کپی کنید. «کپی موارد نیازمند اصلاح» همهٔ موارد ناموفق را جمع می‌کند. خروجی شامل نام، حساب، سرور، MT4/MT5، نوع ورود و علت است؛ رمزها حذف می‌شوند.
۶. بعد از اصلاح می‌توانید دوباره تلاش کنید. توقف، ادامهٔ بررسی را لغو می‌کند؛ حساب‌های قبلاً تأیید و ثبت‌شده حفظ می‌شوند.

## استخراج و تشخیص

- پیام‌های برچسب‌دار فارسی/انگلیسی و قالب معمول نام، حساب، رمز، بروکر/سرور، Demo/Real و MT4/MT5 خوانده می‌شوند. عنوان فرستنده، تیک‌ها و خطوط خالی کنار گذاشته می‌شوند. اطلاعات مبهم برای اصلاح نگه داشته می‌شوند و شماره حساب ساخته نمی‌شود.
- رمز بدون برچسب Investor است؛ فقط Master صریح، نوع مستر را انتخاب می‌کند. رمزها با علائم و حروف اصلی حفظ می‌شوند. ارقام شماره حساب لاتین و متنی هستند.
- نام فارسی به شکل لاتین پیشنهادی تبدیل می‌شود و نام اصلی جدا ذخیره می‌ماند. در ورود متن این انتخاب قابل‌خاموش‌کردن است؛ آوانویسی نام همیشه املای رسمی نیست و قابل‌ویرایش است. در ورود اکسل نیز تبدیل نام فعال است. حساب‌های قبلی خودکار تغییر نام نمی‌کنند.
- نام‌های جایگزین WMMarkets و Windsor و عناوین تأییدشدهٔ کاربر به بروکر یکسان نگاشت می‌شوند.
- اگر شمارهٔ سرور Real مشخص نیست، حداکثر پنج گزینهٔ همان بروکر/پلتفرم به‌ترتیب بررسی می‌شوند. سرور کامل شماره‌دار صریح به گزینه‌های دیگر گسترش نمی‌یابد. گزینه‌ها از فهرست محلی/کش سرورها و پیش‌فرض‌های مجموعهٔ WMMarkets می‌آیند؛ تازه‌کردن فهرست عمومی اختیاری و با زمان درخواست محدود است. هیچ رمز یا شماره حسابی برای دریافت فهرست عمومی سرورها ارسال نمی‌شود.
- فقط تأیید مستقیم ورود، سرور نهایی را انتخاب می‌کند. ترتیب بررسی سرورهای موفق قبلی به خاطر سپرده می‌شود. همهٔ گزینه‌های ناموفق، همراه دلیل موجود، گزارش می‌شوند؛ رد همهٔ سرورها به معنی اثبات رمز اشتباه نیست.
- نام اصلی و اطلاعات سرور در ذخیره‌سازی/پشتیبان قابل‌حفظ‌اند. حساب تکراری بر اساس شماره حساب رد می‌شود. دو حساب یک اسم حفظ می‌شوند؛ تعارض اطلاعات یک شماره باید اصلاح شود.

## اکسل و نتایج

ورود اکسل، الگوی اکسل، خروجی عمومی اکسل برنامه و خروجی نتایج باقی هستند. «اطلاعات به Excel» فایل قابل ورود مجدد با رمزهای واردشده می‌دهد؛ فایل را خصوصی نگه دارید. «ذخیره نتیجه» و نتیجهٔ خودکار رمزها را ندارند. نام اصلی در ستون اختیاری OriginalName نگهداری می‌شود. هشدار دقت شمارهٔ عددیِ بلند اکسل با بازبینی جدول یا خروجی/ورودی مجدد پنهان نمی‌شود؛ شماره باید صریحاً اصلاح شود.

رد ورود ممکن است ناشی از حساب، رمز، سرور یا غیرفعال‌بودن حساب باشد؛ پیام متاتریدر همیشه این‌ها را تفکیک نمی‌کند. پایان زمان انتظار به معنی رد رمز نیست. برای تشخیص واقعی، همان متاتریدر بروکر باید روی ویندوز نصب و شبکه در دسترس باشد. هیچ تضمینِ ورود موفق برای اطلاعات ناقص یا حساب غیرفعال وجود ندارد.

حساب‌های ناموفقِ ازقبل ذخیره‌شده حذف نمی‌شوند. شرط «ثبت فقط پس از تأیید» در مسیر جدید ورود متن و اکسل اعمال می‌شود. موارد ناموفقِ این نوبت در جدول و خروجی نتیجه باقی می‌مانند؛ با بستن پنجره، متن خام و رمزهای پیش‌نمایش از حافظهٔ فرم پاک می‌شوند.

## Scope and validation

The existing native MT4/MT5 reporters, financial formulas, main-table appearance, Telegram/Bale and terminal launch/review behavior are retained. Import uses the existing owned private login verifiers, not the student's running terminal. New account metadata is appended compatibly to existing account files and backups. Failed/unconfirmed imports are not committed to the roster. The prior background verification queue remains for previously saved accounts.

Validation uses synthetic text/Excel inputs, mock login verifiers, temporary account stores and actual .NET/Mono UI flows at normal and125% scale. It covers extraction, original-name preservation, literal passwords, numeric precision, conflicting/duplicate accounts, server candidate order/cancellation, positive-only registration, copyable corrections, backup and restart. Actual Windows/broker logins, real public-server API availability and official Latin spelling require user-side validation; no supplied real student credentials are used in these checks. Exact test outcomes and release hashes are recorded in VERIFICATION-3.60.0.json.
