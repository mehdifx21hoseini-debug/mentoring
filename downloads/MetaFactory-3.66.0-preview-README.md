# MetaFactory 3.66.0 preview

Changes are limited to student text/Excel import recognition, server resolution, its import options, and relevant tests/template instructions. Launch/close, native reporters, the approved main-row appearance, financial calculations, bots and storage retain3.65.1 behavior.

- Pasted messages are separated at sender/name/account boundaries. Incomplete records remain visible instead of borrowing account/password/platform values from the following person. Name prefixes and known greeting/annotation lines are handled separately. Long inline messages and nonbreaking-space separators, checkmarks and the pointing-hand field separator are accepted.
- Additional field spellings include Log in, Acc. Number, Investor pas., akant, Meta5, Persian account/password/investor/broker/platform labels and the supplied parenthetical MT4/MT5 and Real/Demo hints. Label normalization is separate from password extraction: password characters and case remain unchanged. Conflicting password/platform/server fields are retained as review problems.
- WM Market, WMMarket, WMarket, Windsor/Windsore, Persian Windsor spellings and the requested trusted-broker aliases resolve to WMMarkets. A visible Missing broker: WMMarkets option applies only to new input; it can be disabled. Text entry mirrors this option. No broker is silently borrowed from another student's message.
- Excel and text use the same broker/platform/type resolver. Bare Demo/Real is an account type, not a complete server name. Optional Broker and AccountType columns are supported, as are flexible header spellings. Full supplied server names remain exact, including WMMarkets-REAL, to preserve existing-account reimports.
- Numbered account-type input such as Real6 is expanded using the supplied broker and tried first. Other candidates come from that platform's local/cached public server catalogue, with successful-server preferences. Real6 and later existing names can be included; missing numbered alternatives are not invented. If no catalogue exists, only the existing platform-specific WMMarkets default is offered. Text entry can refresh the catalogue through the existing public server-list workflow.
- Candidate checks are sequential and stop at direct successful login. Each gets a30-45-second budget within a bounded total of at most5minutes and16candidates. Busy-verifier, cancellation and invalid-secret conditions keep the existing safeguards; an inconclusive candidate run does not claim that the password is definitely wrong. Exact-server verification retains its existing bounded transient recovery. Existing-account replacement still requires proof before changing credentials, and failed new connections remain outside the roster.
- Input Excel exports append broker/type/source metadata while retaining existing columns. New input can receive the requested Latin-name conversion; roster exports preserve their original names on reimport. Original names, account digits, candidate intent, passwords, long-number precision warnings and folder metadata survive the appropriate round trips. Result/issue copies still exclude passwords, and Copy issues remains name plus account only.

Use: paste the original messages, leave the missing-broker WMMarkets option selected for this batch, refresh the catalogue if needed, and inspect the preview before verification. The supplied message patterns are tested as13records,12unique accounts and one exact duplicate. Recognition means ready for verification, not proof that every password or server is valid.

Validation uses synthetic passwords and substitute identities for all published fixtures. It covers the13-record pattern, ownership/platform/password separation, long Unicode whitespace, incomplete/conflicting records, aliases, Excel round trips and precision protection, server discovery/Real6 ordering, failed-account exclusion, replacement/no-change/folder recovery, and actual import dialogs in English/Persian at normal and125% scaling. Native MetaTrader/broker authentication and catalogue availability on the affected Windows computer are not established by Mono/Linux synthetic tests. The real student messages, workbook and credentials are not bundled.
