# MetaFactory 3.66.1 preview

Fixes the private MT5 login verifier used by student import. Existing normal terminal opening/closing, live reporting, MT4 verification, financial calculations, text recognition, replacement safeguards, bots and storage policy retain3.66.0 behavior.

- Private MT5 login starts through the SDK with the requested account/server/password from its first connection. It no longer opens an anonymous terminal first. A separate fresh api.login acknowledgement and connected account/server identity match remain mandatory; cached account_info alone never proves success.
- Initialization and login have independent bounded budgets. Cold initialization allows60seconds, warm initialization30seconds, and login30-60seconds according to the existing caller budget. Helper startup, identity verification and IPC shutdown are also bounded, with a monotonic overall ceiling of at most180seconds per check. A slow initialization therefore does not consume the entire old30-second login response window. This does not add a wait when a successful or rejected response arrives sooner.
- Token-bound, size/count-bounded progress/result packets identify helper startup, initialization, explicit login, account/server verification and shutdown. Duplicate progress cannot extend a deadline. Stage/code diagnostics distinguish SDK/IPC failure from the SDK's explicit authentication rejection(-6). A helper exit is not labeled as an elapsed timeout. Import preview/result workbooks retain the stage and safe numeric SDK code; passwords, exception text and raw SDK descriptions are not printed.
- Only an explicit native authentication rejection may reject credentials. Fresh ACK, exact account/server binding and request-token checks remain. Cancellation, invalid/old/mismatched responses, helper failure and incomplete verification cannot add an account or overwrite previous credentials. Existing ownership checks govern cleanup; only the reserved private terminal is adopted, hidden or closed.
- MT5 candidate-server totals account for the separate-stage budget, retaining the existing five-minute overall candidate limit. MT4 candidate timing is unchanged. Existing retry policy remains bounded and does not retry conclusive credential rejection automatically.
- The new import helper is a small content-addressed Python resource alongside the existing runtime. The legacy runtime archive, legacy helper, runtime tag, report-login contract and symbol-probe behavior are unchanged. It does not create another complete Python runtime per account. Normal report/MT4 verifier bodies and normal launch/close/live sources are protected by a source comparison.

After installing, retry the unconfirmed MT5 accounts, or paste their original messages again. Unchanged existing accounts retain the3.66.0 import behavior. A remaining failure should now identify its stage/code; Save results is the useful diagnostic. Recognition and synthetic success tests do not certify the four real broker accounts.

Validation:45Python tests for legacy and new helpers, with simulated slow initialization/login, fresh ACK and identity guards, errors/rejections/exceptions/privacy, framing and persistent service. C# protocol/deadline/resource-deployment tests, owned private-workspace tests, text/import/replacement/UI/live regressions, main application tests, Framework4.5 build and exact installer/resource verification. Tests run on Linux/Mono with synthetic SDK responses; real Windows MT5 startup, updater/process behavior, broker responses and student credentials require validation on the affected computer.
