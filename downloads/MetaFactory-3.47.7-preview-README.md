# MetaFactory 3.47.7 preview — MT5 self-update login and live-start recovery

شواهد گزارش ۳.۴۷.۶: دقیقاً ۲۴ نسخهٔ MT5 پیش از شروع، در LiveReporter.Prepare با پیام بررسی مستقیم Sandboxie و Access is denied متوقف شده‌اند؛ این عدد شاهد سقف ۶۲ ترمینال نیست. چند MT5 دیگر هنگام LiveUpdate بسته/دوباره اجرا شده‌اند. کد قبلی فایل شروع با نام یکتا را پس از خواندن اولیه حذف می‌کرد، سپس برای updater فایل mtm-start.ini بدون تنظیمات کامل اکسپرت می‌ساخت؛ درحالی‌که updater همان /config یکتای اصلی را دوباره می‌خواند. ژورنال cannot load config، پنجرهٔ Login و اجرای بدون چارت با این نقص سازگارند. خاموشی Algo Trading برای گزارش‌خوانِ بدون فرمان معامله، علت کافی برای گزارش‌نگرفتن نیست.

اصلاحات:
- بررسی دسترسی Sandboxie ابتدا فهرست PIDهای واقعاً داخل باکس را می‌گیرد و فقط جزئیات همان‌ها را بررسی می‌کند؛ از پرس‌وجوی جزئیات پردازش‌های عادی/محافظت‌شدهٔ نامرتبط پیش از فیلتر Sandboxie جلوگیری می‌شود. باکس ناشناخته یا دسترسی مستقیم تأییدنشده همچنان خطا می‌دهد؛ امنیت باکس تغییر نمی‌کند. رفع عملی Access denied هنوز به آزمون ویندوز مقصد نیاز دارد.
- فایل موقت شروع زندهٔ MT5 تا ۱۵ دقیقه از شروع یا بازیابی به‌روزرسانی نگهداری می‌شود؛ دریافت تأیید خواندن اولیه دیگر آن را زود حذف نمی‌کند. در این مدت پایش اضافی ژورنال برای تصمیم حذف انجام نمی‌شود. بستن برنامه آن را پاک می‌کند؛ فایل‌های منقضی‌شدهٔ باقی‌مانده در پاکسازی شروع برنامه حذف می‌شوند. فایل موقت ممکن است اطلاعات ورود داشته باشد؛ افزایش عمر آن برای بازراه‌اندازی updater عمدی است.
- زمینهٔ بدون رمزِ شروع اکسپرت و مسیر اصلی فایل در حافظهٔ مدیریت اجرا نگهداری می‌شود. اگر MT5 برای به‌روزرسانی بسته شود و فایل اصلی موجود نباشد، تنظیمات حساب و اکسپرت کامل به‌شکل اتمی در همان نام اصلی بازسازی می‌شوند. مسیر بازیابی قدیمی با پاکسازی ۱۰ ثانیه‌ای برای این حالت استفاده نمی‌شود. مسیر اصلی فقط باید فایل تولیدشدهٔ همان نسخه باشد؛ فایل دلخواه بازنویسی نمی‌شود.
- طبق درخواست کاربر، تنظیم AllowLiveTrading=0 در مسیر شروع پایش MT5 اعمال می‌شود؛ مجوز معامله فعال نمی‌شود و گزارش‌خوان به آن وابسته نیست. تغییر به اجراهای جدید از متافکتوری اعمال می‌شود، نه ترمینال ازقبل‌باز. DLL برای MT5 فعال نشده است.
- وقتی نسخهٔ MT5 فهرست نماد ندارد، نمادهای شناخته‌شدهٔ همان سرور از نسخه‌های خصوصی گزارش‌گیری و در صورت نیاز نصب بروکر جستجو می‌شوند تا بازگشت بی‌دلیل به GBPUSD قدیمی کمتر شود. این جای تأیید بومی نماد/اتصال را نمی‌گیرد.
- کد بومی هر دو اکسپرت MT4/MT5، اسکریپت‌های دستی و محاسبات مالی تغییر نکرده‌اند. سیاست فایل شروع و پروفایل تک‌نموداری MT4 حفظ شده است. روی پنجرهٔ ورود خودکار OK زده نمی‌شود و شکست رمز، موفق فرض نمی‌شود.

آزمایش: متافکتوری و MT5های آزمایشی را ببندید، نسخه را نصب کنید و ابتدا یک موردی که قبلاً cannot load config/پنجرهٔ ورود داشت و یک مورد از گروه Access denied را از متافکتوری اجرا کنید. پس از کامل‌شدن شروع، نمودار، اکسپرت و تازگی گزارش را بررسی کنید. در صورت شکست، بررسی سیستم تازه و ژورنال همان حساب را ارسال کنید؛ رمز نفرستید. سپس تعداد را تدریجی بالا ببرید تا ظرفیت واقعی و مصرف حافظه مشخص شود.

این اصلاح سقف تعداد جدیدی اضافه نمی‌کند و مشکل تمام حساب‌ها یا منابع ویندوز را تضمین نمی‌کند. در نمونهٔ تشخیصی، رم آزاد حدود ۱٫۱ گیگ و RAM کل ۷٫۹ گیگ بوده است؛ خطای آماده‌سازی Sandboxie از فشار حافظه جداست. سرویس Sandboxie، MCP پورت22346 و کد خروج صفر/منفی به‌تنهایی دلیل قطعیِ یک علت مشترک نیستند.

محیط ساخت Windows/MetaEditor/بروکر ندارد. بسته سورس کامل و نصب‌کننده دارد و فاقد گزارش خصوصی، رمز و اطلاعات واقعی حساب‌هاست.

اعتبارسنجی: ۲۲۰۶ آزمون منطق و فایل موفق، صفر خطا؛ یک آزمون قدیمی Python اجرا نشد. ۲۰ بررسی مصنوعی رابط، شامل مسیر واقعی PutStartFileBack برای بازسازی نام اصلی و حفظ Expert/ExpertParameters/ProfileLast/حالت بدون معامله و ثابت‌ماندن سیاست MT4، موفق بود. نسخه‌ها، منابع، تطابق برنامهٔ داخل نصب‌کننده و یکسان‌بودن کد اکسپرت‌ها و محاسبات بررسی شدند. این آزمون‌ها اجرای Windows/LiveUpdate بومی، Sandboxie واقعی یا بروکر نیستند.
