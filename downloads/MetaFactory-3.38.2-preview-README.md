# MetaFactory 3.38.2 — بهبود بازیابی گزارش‌گیری MT5

در فایل عیب‌یابی ۱۳:۳۹ نسخهٔ 3.38.1، هیچ گزارش تازه‌ای ثبت نشده بود: گزارش‌خوان حساب اول روی XAUUSD@ شروع شد ولی حین خواندن تاریخچه اتصال قطع شد؛ سه اجرای بعدی روی EURUSD شروع گزارش‌خوان را تأیید نکردند. علت قطع ارتباط بروکر از این فایل معلوم نیست. پیام توقف منابعِ نوبت قبلی در این اجرا ثبت نشده و رابط Python نیز هنوز به مرحلهٔ ورود نرسیده است.

این نسخه دو ضعف قابل اصلاح در این مسیر را برطرف می‌کند:

- چارتی که گزارش‌خوان روی آن با درخواست و اتصال حساب درست شروع شده، برای همان سرور حفظ می‌شود؛ حتی اگر بعداً دریافت تاریخچه شکست بخورد. این شواهد هرگز معادل گزارش موفق نیست و شمارندهٔ گزارش تازه را زیاد نمی‌کند.
- هنگام قطع کوتاه اتصال در خواندن تاریخچهٔ MT5، حداکثر هشت ثانیه فرصت بازیابی داده می‌شود. پس از اتصال، تاریخچه دوباره انتخاب و پایداری آن از نو بررسی می‌شود. تغییر حساب/سرور، قطع طولانی یا پایان مهلت کل، گزارش موفق تولید نمی‌کند. زمان انتظار کل همان سقف قبلی است.

همچنین توقف از مسیر دکمهٔ توقف و بستن فوری برنامه در فایل عیب‌یابی جدا ثبت می‌شود. کد گزارش MT4، محاسبات معاملات و تعداد اجراهای همزمان تغییر نکرده‌اند.

برنامه را ببندید و این نسخه را نصب کنید. نخست فقط همان دو یا سه حساب اول MT5 را گزارش بگیرید. برای گزارش‌خوان جدید MT5، برنامه یک‌بار از MetaEditor نصب‌شده برای ساخت نسخهٔ 1.25 استفاده می‌کند. پس از پایان، تعداد گزارش تازه و فایل عیب‌یابی را بررسی کنید؛ گزارش قدیمیِ کش‌شده موفقیت تازه نیست.

این بسته شامل فایل نصب و سورس کامل است. آزمون‌های خودکار، اجرای زندهٔ ویندوز و اتصال بروکر را جایگزین نمی‌کنند. در این محیط MetaEditor و بروکر به‌صورت زنده آزمایش نشده‌اند؛ علت اصلی قطع ارتباط شبکه هنوز از شواهد فعلی قطعی نیست.

اعتبارسنجی: ۱۷۰۳ بررسی C# و ۳۷ آزمون Python موفق بودند. شش آزمون جدید، بدنهٔ واقعی تابع MQL خواندن تاریخچه را با API شبیه‌سازی‌شده در C++ اجرا می‌کنند: مسیر سالم، قطع کوتاه، قطع طولانی، تغییر حساب، قطع‌های تکراری و توقف. این آزمون جای کامپایل MetaEditor را نمی‌گیرد. تطابق نسخه و محتوای نصب‌کننده نیز تأیید شد. یک بررسی قدیمی وابسته به python3 داخل کانتینر Mono اجرا نشد؛ آزمون‌های Python روی میزبان انجام شدند.
