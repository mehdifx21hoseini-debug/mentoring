# MetaFactory 3.64.4 preview

Changes are limited to the two-line main-list live/day summary, closed-stop counts and identifying an older MT4 observer still running after an application update.

- Row height stays unchanged at two lines. First line is a measured, compact English summary. While any position is open it shows only open-position floating P/L, open-position count and known current missing-stop count, for example `Open +$0.09 · 2 open · No SL: 1`. Realized daily profit is excluded from this amount. When no position remains open, the first line switches to the verified closed trading result of the broker day, for example `Day +$70.00 · 7 trades · No SL: 3`. The existing money sort uses the same displayed amount. Underlying account/report/bot financial arithmetic is unchanged.
- The second line retains green Live with actual heartbeat age, or the existing report age/previous-report state. The no-stop count is inline on the first line instead of repeating its badge beside freshness. No new row controls, fonts or timers; English/Persian layout directions are preserved while these metrics use English labels and Latin numbers.
- Open No SL is based on current known zero stops. Closed No SL is based on a known numeric zero stop recorded at close for trades closed in the same displayed broker-day range. It does not claim that a trade never had a stop or lacked one at entry; MT4 does not retain that full timeline. The tooltip states the basis. A missing/invalid final-stop token is not inferred as zero. Optional `MF_FINAL_SL_UNKNOWN` cache metadata preserves this uncertainty while retaining every legacy numeric field and financial fallback. Mixed evidence shows a lower bound; wholly unknown evidence is a dash. Zero missing stops adds no warning.
- MT5 still uses the existing closing-deal daily count. A closed-stop count is shown only when the day's exits map one-to-one to its closed position records. Partial/multiple exits, reversal/aggregate mismatch or incomplete evidence yield an unknown stop count rather than a fabricated exact result. Native MT5 reporter and all period/account calculations are unchanged.
- A fresh pending-history frame can continue updating open floating P/L and balance immediately through the existing one-second reception path. After the final position closes, the daily result remains unknown until its historical proof is accepted; it is not silently set to zero or borrowed from an old baseline.
- MT4 observer1.07 emits an optional bounded `E` version record in its existing heartbeat. The reader accepts both legacy and versioned frames, retaining all account, session, replay, freshness and full-history checks. While a fresh MT4 feed has not reported the current observer version, its footer says `Restart reporter`; its separately validated financial data can still be displayed. Once the new observer heartbeat arrives, that notice disappears. Pending history continues to say `History pending` until proof succeeds. System check includes the actual heartbeat's observer version.
- The user's latest screenshot contained an MT4 EA alias whose source prefix matches the old observer, despite an updated MetaFactory application. Updating MetaFactory does not hot-replace an EA already executing inside MT4. The previous1.06 bounded All History recovery is retained unchanged in1.07. No forced hot replacement, automatic terminal closure/restart or additional terminal process was introduced.

Activation: install3.64.4. Close the affected reporting terminal using MetaFactory's Close command, then Open it through MetaFactory once. Merely clicking Show on an already-open terminal keeps its existing EA. Normal startup compiles/deploys observer1.07 through the installed MetaEditor and existing content-addressed deployment/migration path. A new heartbeat without `Restart reporter` confirms the version marker has arrived. The existing new-session binding and identity checks still apply.

Validation: MT4/MT5 and both UI languages; floating-only versus day-net transition; last-open and all-closed cases; current and closed zero/positive/unknown stops; MT5 partial-exit mismatch; missing historical baseline; stale/future/wrong-account feed rejection; legacy/new/duplicate/malformed observer records; final-stop cache provenance without numeric financial changes; actual MainForm live and cached transitions, warning removal on actual new-version heartbeat, measured text bounds, and synthetic screenshots at normal/125%. Main application, open-stop, pending-live and report-status regressions pass. Existing MT4 recovery function bodies execute in the mocked terminal API tests. Framework4.5 reference build and exact installer/resources checked.

Limits: synthetic Mono/Linux GUI and mocked terminal API. Native MetaEditor compilation and affected Windows/broker recovery require checking after the one-time reporting-terminal restart. No guarantee of zero broker/network/render latency. If the new observer still reports unconfirmed history, the bounded session recovery diagnostic is required to identify the remaining broker/history discrepancy; the UI never certifies missing data by changing its label.
