# ابزار آزمایش منابع پنجرهٔ ویندوز — نسخه 1.0.0

این ابزار جدا از MetaFactory است و نسخهٔ برنامهٔ اصلی را تغییر نمی‌دهد. هدف، مقایسهٔ ایجاد یک پنجرهٔ بسیار کوچک پنهان و تایمر در دسکتاپ فعلی با یک دسکتاپ موقت جداست. هیچ دسکتاپی به کاربر نمایش داده نمی‌شود و صفحهٔ کاربر عوض نمی‌شود.

## روش استفاده

1. متاتریدرهای باز را ببندید تا ویندوز به حالت عادی برگردد. برای مقایسه، تنظیمات MetaFactory را تغییر ندهید.
2. فایل `MetaFactory-Window-Probe-1.0.0.exe` را اجرا کنید. پنجره‌ای باز نمی‌شود؛ طبیعی است. روی Desktop یک فایل `MetaFactory-Window-Test.txt` ایجاد می‌شود. این فایل نشانهٔ شروع ثبت است. ابزار را یک بار اجرا کنید.
3. در MetaFactory همان گروه قبلی را Run کنید.
4. وقتی مشکل بازشدن متاتریدرها یا پنجره‌های ویندوز تکرار شد، حدود ۶۰ ثانیه صبر کنید تا چند نمونه ثبت شود.
5. اگر پوشه‌های ویندوز باز نمی‌شوند، مثل قبل چند متاتریدر را ببندید تا ویندوز پاسخ دهد.
6. فایل `MetaFactory-Window-Test.txt` روی Desktop را ارسال کنید. این بار فایل آزمایش جدید لازم است؛ لاگ قبلی برای تحلیل قبلی کافی بود.

اگر Desktop قابل نوشتن نباشد، همان نام فایل در `%APPDATA%\MT Manager` ذخیره می‌شود. اگر هیچ فایل جدیدی ایجاد نشد، ابزار شروع به ثبت نکرده است؛ نتیجهٔ موفقی فرض نکنید.

## رفتار و محدوده

- نیازی به Administrator ندارد. چیزی نصب نمی‌کند، رجیستری را تغییر نمی‌دهد، متاتریدر یا فرایند دیگری را باز و بسته نمی‌کند، ارتباط شبکه ندارد و اطلاعات حساب، رمز، عنوان پنجره یا خط فرمان را نمی‌خواند.
- هر ۳۰ ثانیه یک جفت آزمایش کوتاه انجام می‌دهد؛ پنجره و تایمر ساخته‌شده توسط خود ابزار پاک می‌شوند. دسکتاپ آزمایشی با ظرفیت درخواستی ۱۰۲۴ کیلوبایت ساخته و بعد از پایان نخ آزمایش بسته می‌شود. این تنظیم فقط به همان شیء موقت مربوط است و مقدار سراسری ویندوز را عوض نمی‌کند.
- نهایتاً پس از ۶۰ دقیقه تمام می‌شود. اگر آزمون یا پاک‌سازی منابع تأیید نشود، آزمایش‌های بیشتر متوقف می‌شوند. برای توقف زودتر می‌توان فقط فرایند `MetaFactory-Window-Probe-1.0.0.exe` را در Task Manager پایان داد.
- فایل جاری و یک فایل قبلی نگه داشته می‌شوند؛ هرکدام حداکثر ۱ مگابایت. فایل قبلی با پسوند `-previous.txt` است. فایل ناشناختهٔ موجود بازنویسی نمی‌شود.
- شمارش نام‌های `terminal` و `terminal64` صرفاً شمار فرایندهاست؛ اثبات ورود، بازبودن پنجره یا دیتای زنده نیست.

## معنی نتیجه و محدودیت

این یک ابزار تشخیصی است؛ مشکل ظرفیت را رفع نمی‌کند. اگر آزمایش دسکتاپ فعلی شکست بخورد و دسکتاپ جدا موفق شود، تفاوت قابل‌اندازه‌گیری برای بررسی منابع دسکتاپ به دست می‌آید. شمارهٔ خطای هر API حفظ می‌شود؛ از این نتیجه به‌تنهایی نوع دقیق حافظه یا رفع مشکل با افزایش Desktop heap نتیجه‌گیری نمی‌شود.

اگر ساخت دسکتاپ جدا با خطای دسترسی رد شود، این موضوع دلیل کمبود رم نیست. اگر هر دو پنجرهٔ کوچک ساخته شوند، توانایی اجرای کامل متاتریدر اثبات نمی‌شود. آزمایش‌ها پشت سر هم انجام می‌شوند، نه هم‌زمان. موفقیت ساخت تایمر، دریافت پیام یا اجرای ربات/گزارش‌گیری را بررسی نمی‌کند.

ساخت با Reference assemblies دات‌نت۴٫۵ و تست‌های ساختگی API در Mono/Linux انجام شده است. فراخوانی واقعی API ویندوز و رفتار زیر فشار باید روی ویندوز کاربر آزمایش شود؛ رفع قطعی علت هنوز ادعا نمی‌شود.

## سورس و ساخت

فایل اصلی `source/WindowProbe.cs` و آزمون‌ها `source/ProbeTests.cs` هستند. `source/build.sh` برای Mono است؛ متغیر اختیاری `MF_REF45` مسیر Microsoft .NET Framework 4.5 Reference Assemblies را می‌گیرد.

در Developer Command Prompt ویندوز نیز می‌توان ساخت:

```
csc /optimize+ /platform:anycpu /target:winexe /r:System.Web.Extensions.dll /out:MetaFactory-Window-Probe-1.0.0.exe WindowProbe.cs
csc /r:System.Web.Extensions.dll /r:MetaFactory-Window-Probe-1.0.0.exe /out:ProbeTests.exe ProbeTests.cs
ProbeTests.exe
```
