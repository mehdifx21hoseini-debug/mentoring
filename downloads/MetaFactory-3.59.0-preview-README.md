# MetaFactory 3.59.0 preview — trade counts and per-trade return percentages

Today now shows only Closed and Open counts with the existing report-age line. Ordinary, validated-live and history-pending paths all use counts: no money, SL tag or DD string is rendered there. Unavailable counts remain dashes; known zero is distinct from unknown. Pending history is labelled Live/syncing and does not claim a fresh complete report. Balance and Overall DD remain in Account information. Prior-report badges remain for failed refreshes. The Today header sorts closed count, then open count, and toggles back to the underlying order; it no longer sorts an invisible profit amount. The default latest-trade/open-positions-first sort is retained.

Server-cell text uses the smaller app font. Other cell fonts and column structure are retained; the tooltip still supplies the complete server name when the rendered value is truncated.

The student report's per-trade Result now includes money and a signed percentage of the actual account balance immediately before entry, e.g. +$26.80 · +0.78%. The separate SL risk column remains a potential stop-loss risk estimate and is explicitly labelled SL risk. A realized gain/loss percentage is not substituted into missing SL risk. Result columns receive more width, including expanded trade rows in multi-day views.

The new return denominator is reconstructed from the validated whole-history balance ledger, including actual funding, withdrawals and previously booked results. It is not current equity/current balance, allocated margin, day-start balance or the cashflow-normalized DD curve. An indexed prefix timeline is built once per view construction. MT5 entry-deal IDs and full-ledger milliseconds resolve entry costs and prior funding when available. Different balance-changing events with ambiguous same-entry timestamp ordering are not guessed. Missing/incomplete/unreconciled history, nonpositive entry balance and nonfinite values yield a dash. The existing net result includes its reported commissions/swap/fees. Floating rows are labelled floating, and their numerator updates against the retained proven entry balance without mutating the earlier view.

Existing monetary results, SL risk, overall DD/PF formulas and native reporter/launch transport are retained. Native script/codec sources are unchanged. The new return calculation is a local read-only presentation metric. No new real broker or provider execution was tested here.

Validation includes synthetic ledger tests for funding, withdrawals, overlapping positions, entry fees, exact/ambiguous MT5 timing, invalid proof, credit, live numerator updates and signed formatting; ordinary/live/pending count-only UI, unknown counts and count sorting; student result integration and inline details; EN/FA normal and125percent display checks; application tests and installer/resource/version verification. Public artifacts contain no supplied bot token/private connection file.
