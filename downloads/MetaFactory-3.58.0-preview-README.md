# MetaFactory 3.58.0 preview — account summary and recent-trade ordering

The existing main-window structure is retained. The reserved account column now displays two neutral lines: reported Balance and verified Overall DD. Equity is not displayed in this column. DD reuses the same full-history relative trading-balance drawdown as the account report; a missing/invalid proof produces a dash. The hover detail includes full balance, overall DD, whole-account profit factor, open-position count at the report snapshot and report timestamp. Invalid/mismatched account data and nonfinite amounts do not become invented zeros. MT5 factor requires its existing whole-position factor proof.

For ordinary snapshot reports, Today displays closed-trade net and closed-trade count with report age beneath it. It does not merge floating open-position profit into the displayed closed result. Live Today rendering retains its existing behavior. A failed refresh retains the earlier verified report with a small Previous report badge; a report from an older broker day is not relabelled as today's closed result. An unread account displays unknown values.

Account information and Today have larger column weights/minimum widths. Name/account/server/status columns are narrower; the copy badge keeps a minimum width based on the full copy ID. Account metrics remain visible at normal and125percent display scale. Full report values are also available in hover details.

Completed ordinary reports return to a compact result strip with fresh/failed counts, duration and Details. Details expand/collapse inside the same window, without a result dialog. Cached/stopped/failure outcomes remain distinct from fresh success. Existing stop/progress and live-launch summary behavior is retained.

The default view sort is Latest trade, open positions first. These are trading positions in the last verified report, not open MetaTrader windows. Accounts with reported open positions precede accounts without them; remaining accounts are ordered by the most recent trading/close timestamp, newest first. Known broker offsets normalize timestamps to UTC before cross-server comparison. Missing times are not guessed; known open positions retain priority, and unknown times follow known times within their group. Ties preserve the saved underlying order. The Sort menu includes this view mode and Saved/manual order; existing permanent arrangement choices remain. Sorting works on each current filtered/folder view and updates after reports.

Snapshot reports remain snapshots until refreshed. No native report pipeline, terminal transport, reporter script or financial formula change is included. Telegram/Bale automatic token setup and compact student actions are retained. No supplied real bot token/private connection file is embedded.

Verification: synthetic financial/presentation/sort tests including account binding, invalid/missing proof, nonfinite balance, floating exclusion, broker offsets, priority/ties and failure preservation; main UI/inline details at normal and125percent scale in English/Persian; existing report-finish/stop and application tests; installer payload/version and public artifact checks. Actual broker/API executions were not newly tested by these Mono UI/model checks.
